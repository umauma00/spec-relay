# canvas で見る（試験中）

Copilot の canvas（チャットの横に開く画面）に、移行の進み具合・レビュー画面・承認済みの仕様と、作ってあればコードガイドを出します。中身は `render.mjs` の HTML と同じデザインです。どの項目にも「これを聞く」ボタンがあり、押して書いた質問がそのままチャットに届きます。進行中の変更のレビュー画面では、項目を確認済みにしたり、判断やレビュー担当の名前を書いたりでき、canvas がそのまま review.md に書き込みます。

> canvas は Copilot 側で試験中の機能です（2026-11-18 時点）。Copilot app は提供済み、VS Code は Preview（1.142 以降、設定 `chat.canvases.enabled`、Copilot ハーネスのローカルセッションのみ）、Copilot CLI は実験的機能（`--experimental`）です。仕様が変わることがあります。canvas が使えないときは、今までどおり `render.mjs` の HTML をブラウザーで開いてください。

## 開き方

プラグインとして入れると、canvas の拡張（`com.github.copilot/extensions/spec-relay-canvas/`）も入ります。チャットで頼んでください。

```text
spec-relay の canvas を開いて
extract-billing-invoice のレビュー画面を canvas に出して
billing/invoice の仕様を canvas で見せて
```

| 画面 | 中身 |
|---|---|
| 進み具合 | 全体の状態、いまの作業と誰の番か、やること、レビュー待ちの変更（未確認の数）、機能ごとの状態。各画面へのリンク |
| レビュー画面 | `render.mjs --change` と同じ。確認印、残りの数、元コード。進行中の変更なら、確認・判断・レビュー担当のボタン |
| 仕様の一覧・仕様 | `render.mjs --spec` と同じ。検索つき |
| コードガイド（作ったときだけ） | `render.mjs --guide` と同じ。質問への AI の回答をその項目の下に出し、役立ったものを Q&A に保存できる（[コードガイド](GUIDE.md)） |

- `openspec/` の下のファイル（変更・仕様・スクリーンショット・計画・設定）が変わると、数秒で画面も変わります（作り直しは要りません）。元コードや移行先のコードの変更では変わりません。
- 「これを聞く」で送った質問は、`[canvas]` で始まるメッセージとしてチャットに届きます。AI はそれに答えます。**質問であって、承認や判断にはなりません**。
- 画面の「判断を書く」で判断を書いて、「確認済みにする」を押せば、その項目を承認したことになります。

## レビュー画面から書き込む（0.18.0 から）

進行中の変更（アーカイブ前）のレビュー画面では、各項目の下に次のボタンが出ます。

| ボタン | review.md で変わること |
|---|---|
| 確認済みにする／確認を外す | その項目の行の `[ ]` と `[x]` |
| 判断を書く（質問 Q の項目だけ） | その行の `decision:` の後ろ（1行、500文字まで。前の判断と置き換え） |
| 判断を書いて確認済みにする（判断がまだない Q） | 上の2つを続けて |
| レビュー担当（画面の上） | `Reviewer:` の行（なければ見出しの下に足す） |

- **自分で review.md を直したのと同じ扱いです**。AI はそのファイルを読んで進めます。変更を完了（アーカイブ）してよいかは、今までどおりチャットで伝えてください。canvas で全部確認済みにしても、それだけではアーカイブしません。
- 書き込むのは、その変更の review.md の自分の行だけです。ほかの行の改行コードもそのままです。項目と `Reviewer:` の行は gate と同じ読み方で探します（コメントの中の例は書き換えません）。`decision: ...` や `TBD` のような書きかけは判断として数えません。
- review.md が UTF-8 でない（Windows PowerShell 5.1 の `>` で書いた UTF-16 や Shift_JIS など）ときは、ボタンを出さず、書き込みません。UTF-8 で保存し直してください。
- 判断を書いている途中で review.md がほかで変わったときは、画面を読み直して、書いた文をダイアログに戻します。
- ほかのファイル、アーカイブ済みの変更、仕様の画面には書きません。AI の側には canvas から書く操作がありません。
- 画面を開いた後に review.md がほかで変わっていたら（エディターや AI が直したなど）、書き込まずに画面を読み直します。もう一度押してください。
- 書き込みは、別のファイルに書いてから入れ替えます（途中で止まっても半端なファイルになりません）。BOM と改行コード（CRLF）はそのままです。Windows でエディターがファイルをつかんでいて書けないときは、少し待ってから何度か試し、だめならそう表示します。
- 書き込むたびに `openspec/spec-relay/local/canvas-log.jsonl` に1行（時刻、ファイル、操作、前後のハッシュ）を記録します。この PC だけの記録で、git には入りません（`local/` の `.gitignore`）。AI が波の後に `gate.mjs guard --compare` で比べるとき、波を始めた後の記録だけを順にたどり、波の前の状態から今の状態まで途切れずにつながる変更だけを「あなたが canvas で直したもの」として `canvas` に分けて出します。途中にほかの変更が挟まっていれば、今までどおり割り当て外の変更として止まります。AI はこのファイルを書きません（フックを有効にすると拒否します）。
- 記録は「あなたの操作」を区別するためのもので、改ざんを防ぐものではありません。フックが無効のとき、AI がこのファイルを書くことは技術的には防げません。また、シェルを使える AI がキットのスクリプトを直接呼んで書き込むことも、フックでは見分けられません。
- 画面の中のリンクのうち、canvas の画面どうしのリンクだけが開きます。画像の原寸表示や元コードのファイル、外部のサイトへのリンクは開きません（エディターやブラウザーで開いてください）。
- チャットのセッションが終わると、画面の上に「もう更新されません」と出ます。

## コードガイドで質問する（0.19.0 から）

コードガイド（[GUIDE.md](GUIDE.md)）を作ってあると、画面の上に「コードガイド」のリンクが出ます。

- ガイドの画面で「これを聞く」から送った質問には番号（`q3` など）が付き、AI はチャットで答えたうえで、同じ答えを canvas にも送ります（`post_answer`）。答えは質問した項目の下に出ます。canvas を閉じると消えます。
- モジュールの画面のファイルについての答えには「役に立った（Q&A に保存する）」ボタンが出ます。押すと `openspec/spec-relay/guide/qa/<module>.md` に、そのファイルの今のハッシュと日付と一緒に追記します。canvas が書くファイルは、review.md とこれだけです。
- AI の側の `post_answer` は画面に出すだけで、ファイルには書きません。保存するのはボタンを押したときだけです。
- AI は `open_guide` でガイドの画面を開けます。モジュール名、移行先のファイルのパス、routes.md の URL を渡すと、そのファイルの場所を開きます。

## 守っていること

- 画面を出すのは、拡張が自分の PC の中だけ（`127.0.0.1`）で立てる小さなサーバーです。アドレスには毎回変わる合言葉（ランダムな文字列）が入り、ほかのホスト名からの接続や、ほかのページからの質問の送信は断ります。画面で動くのは、サーバーがその都度の印を付けたスクリプトだけです。
- 質問の文面のうち、対象（画面と項目の名前）は1行にまとめ、画面の名前はサーバーが決めます。
- review.md と Q&A への書き込みも、自分の画面からだけ受け付けます（専用のヘッダーと Origin の確認）。Q&A に保存できるのは、その画面で聞いた質問への回答だけです。どの変更の review.md かはサーバーが決め、シンボリックリンクの先には書きません。
- 見せるのはリポジトリの中の Markdown と画像だけです。リポジトリの外を指すパスやシンボリックリンクの中身は読みません（ファイル名は見出しに出ることがあります）。
- canvas を閉じるとサーバーも止まります。チャットのセッションが終わると拡張も終わります。

## 自分で試す

Copilot なしで、ブラウザーで同じ画面を見られます（質問は端末に表示されます）。

```powershell
node "<キット>/scripts/canvas.mjs" --root .
```

表示された `url` をブラウザーで開いてください。止めるときは Ctrl+C です。

## わかっていないこと

- Copilot app と VS Code が、プラグインに入った canvas の拡張を読み込むかどうか（CLI は 1.0.79 からプラグインの拡張を読み込みます）。
- Windows の Copilot app での表示。
- AI が作業中に質問を送ったとき、すぐ割り込むか、作業の後に答えるか（拡張は「後で」を指定しています）。
- canvas の中で、書き込みの後の読み直しやダイアログが各アプリで正しく動くか（ブラウザーの Chromium では確認済み）。
