# コードガイド（任意）

移行が終わった後（または実装がいくつか終わった後）に、**新しいコードを人が理解するための案内**を作ります。保守や機能追加を引き継ぐ人が、どこに何があるかを探せるようにするものです。工程ではなく任意で、頼んだときだけ作ります。gate はこれを読まず、何も承認しません。

## できるもの

| 入口 | 中身 |
|---|---|
| 技術スタック | 実行環境・フレームワーク・コマンド（移行先の設計の conventions.md から）、ビルドファイル |
| アーキテクチャの図 | モジュールと依存の向き（移行先の設計の architecture.md の `## Modules` 表から、スクリプトが毎回描く） |
| データの持ち主の図 | モジュールと、それが持つテーブル（同じく `## Data ownership` 表から） |
| モジュールから | モジュールごとの概要と、説明済みのファイル数・古い説明の数 |
| 画面と URL から | 画面・URL・エンドポイントごとの処理の場所（ファイルと行）、機能、画面の名前 |
| 機能から | 承認済みの仕様（capability）ごとに、担当モジュールと URL。仕様の画面へのリンク |
| ファイル（モジュールの画面） | ファイルごとの説明、主な部分（名前と行）、コードが変わった後なら注意書き、保存した Q&A |

図は Markdown に保存せず、`render.mjs` が設計から描きます。どのモデルが作っても同じ絵になります。

## 作り方

チャットで頼みます。

```text
コードガイドを作って
billing と sales のモジュールだけコードガイドを作って
```

AI（オーケストレーター）は次の順に進めます。

1. `guide.mjs init`：`openspec/spec-relay/guide/` を作り、`stack.md` と `routes.md`（表のひな形）を置いて、モジュールごとのファイルの一覧を出します。あるファイルは上書きしません。どのモジュールのパスにも入らないコード（起動のファイルなど）は `unassigned` に出て、ガイドには入りません。モジュールのパスは、リポジトリからでも移行先のルートからでも書けます。
2. モジュールごとに説明担当（`spec-relay-guide-writer`）のサブエージェントを並列で動かし、`code/<モジュール>.md` を書かせます。`routes.md` も1人が書きます。
3. `guide.mjs stamp`：説明したファイルの今のハッシュを見出しの下に書きます（まだ書いていない見出しだけ）。ハッシュは BOM を除き、CRLF を LF として計算するので、Windows で取り出したリポジトリでも同じ値になります。
4. `guide.mjs check`：説明に書いた名前がファイルにない、行がない、URL の処理のファイルがない、説明のないファイルがある、を出します。AI は担当に直させて、もう一度確かめます。
5. `render.mjs --guide all` で HTML（`openspec/spec-relay/views/guide.html` とモジュールごとの画面）を作るか、canvas に出します。

## ファイル

```text
openspec/spec-relay/guide/
  stack.md            技術スタック（init が書く。自由に直してよい）
  routes.md           | Page or URL | Method | Handler | Capability | Screen |
  code/<module>.md    ## Overview と、ファイルごとの「### File: <パス>」
  qa/<module>.md      保存した質問と回答（ファイルとハッシュつき）
```

- `code/<module>.md` の主な部分は `` - `InvoiceService.total` (line 42): ... `` の形で書きます。`check` は名前がそのファイルにあるか、その行があるかを確かめます。
- `routes.md` の Handler は `パス:名前:行`、`パス:行`、`パス:名前` のどれかです。
- 説明を書いた後にコードが変わると、画面に「古いかもしれません」と出て、`check` の `stale` に入ります。AI に説明し直させて、そのファイルだけ `stamp --file <パス>` でハッシュを書き直します（`stamp` だけでは、すでにあるハッシュは変えません。説明を直していないのに警告が消えることはありません）。canvas は移行先のコードの変更を見張っていないので、画面に出すには `refresh` で読み直します。

## canvas で質問して、役立った答えを残す

canvas でコードガイドを開くと（「コードガイドを canvas で開いて」、または画面の上の「コードガイド」）、どの項目にも「これを聞く」ボタンがあります。

1. 質問を書いて送ると、チャットに `[canvas]` 付きで届き、AI が答えます。
2. AI は同じ答えを canvas にも送ります。質問した項目の下に表示されます（canvas が動いている間だけ）。
3. モジュールの画面のファイルについての答えには「役に立った（Q&A に保存する）」ボタンが出ます。押すと `qa/<module>.md` に、質問・ファイル・その時のハッシュ・日付と一緒に追記されます。以後はファイルの説明の下に「保存した Q&A」として出ます。
4. 保存した後にそのファイルが変わると、「保存した後にコードが変わりました」と出ます。

保存するかどうかは、ボタン（あなた）が決めます。AI は、あなたがチャットで「保存して」と言ったときだけ同じ形で追記し、`stamp` でハッシュを埋めます。サブエージェントは `qa/` に書きません（フックを有効にすると拒否します）。

## 進捗の表示

`guide/` ができると、TODO リストの最後に「コードガイド（任意）: N ファイル中 M ファイル説明済み」の1行が出ます。全部説明済みで古い説明がなければ完了になります。移行の「いまの作業」にはなりません。

## わかっていないこと

- 大きなモジュール（数百ファイル）で説明担当1人に任せたときの質。1つの `code/<module>.md` を同時に2人には書かせず、残りのファイルは次の波の担当が同じファイルに書き足します。
- 実機の Copilot（CLI・VS Code・app）と Windows での確認はまだです。
